# Micronaut template

Provisioned from [`Qode-Fleet-Control/fleet-template-v1`](https://github.com/Qode-Fleet-Control/fleet-template-v1) — the fleet
lifecycle contract (`bin/`, `fleet.conf`, deploy workflows) with a
Micronaut starter laid on top.

Micronaut 5.2 on Java 25 (Netty server), Maven build, with the `management` feature. `GET /` returns a small JSON document; `/health` is Micronaut Management's health endpoint and answers 200.

## Origin

Generated by the official Micronaut Launch API (launch.micronaut.io — the same generator as the `mn` CLI), 2026-10-05:

    curl -s -o app.zip 'https://launch.micronaut.io/create/default/world.qode.app?lang=JAVA&build=MAVEN&test=JUNIT&javaVersion=JDK_25&features=management'
    unzip app.zip

Micronaut platform 5.2.1, application type `default`, Java 25, Maven, JUnit, feature `management`.
Java 25, not 21: micronaut-maven-plugin 5.x is compiled for Java 25 and fails to load on a JDK 21 Maven
(`UnsupportedClassVersionError ... class file version 69.0`), whatever `javaVersion` Launch was given.

## Run it

**On the fleet** — nothing to do: the fleet clones the repo, injects `PORT` (plus
`DATABASE_URL` and the workspace's other services) and calls `bin/run`, which runs
fleet.conf's `DOCKER_BUILD_CMD` (`docker compose build`) then `DOCKER_START_CMD`
(`docker compose up`, in the foreground). The health check hits `/health`.

**With docker**, locally:

    PORT=8080 bin/run                  # the fleet's docker runtime
    docker compose up --build            # or plain compose; serves on ${PORT:-8080}
    curl http://localhost:8080/health

**Without docker** — a JDK 25 on `PATH`; `./mvnw` (the generator's Maven wrapper) fetches Maven itself:

    FLEET_RUNTIME=process PORT=8080 bin/run

| step | command |
|---|---|
| install | `./mvnw -B -q dependency:go-offline` |
| build | `./mvnw -B -q package -DskipTests` |
| start | `env PORT="$PORT" java -jar target/app-0.1.jar` |

    ./bin/run       # install, build, start in the foreground
    ./bin/start     # start from existing build artifacts
    ./bin/restart   # rebuild and restart
    ./bin/stop      # stop whatever holds the port

## Serving

Listens on `0.0.0.0:$PORT` (default `8080`), read from the environment at run
time. The app is served at the root (`/`) of its own hostname
(`https://<hash>.<FLEET_APP_DOMAIN>/`), so every route, redirect and asset URL is
a plain root path. `/health` answers 200 for the fleet's health check.

## Layout

- `src/main/java/world/qode/Application.java` — generated.
- `src/main/java/world/qode/HomeController.java` — `GET /`.
- `src/main/resources/application.properties` — `micronaut.server.port=${PORT:8080}`, `micronaut.server.host=0.0.0.0`.
- `src/test/java/world/qode/AppTest.java` — generated.

## What differs from stock output

- Added `HomeController` (`GET /`): stock output serves nothing at the root.
- `application.properties`: `micronaut.server.port=${PORT:8080}` and `micronaut.server.host=0.0.0.0`.
- `Dockerfile` is new (Launch writes none for Maven; `mvn package -Dpackaging=docker` needs a docker daemon inside the build): multi-stage, the shaded `target/app-0.1.jar` on `eclipse-temurin:25-jre`.
- `.gitignore`: appended the fleet entries.
- Added the fleet harness: `bin/`, `fleet.conf`, `compose.yaml`, `.dockerignore`, `.github/workflows/`, `docs/fleet-lifecycle.md`.
